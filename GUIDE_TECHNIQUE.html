1. Introduction et Périmètre

Evolve Staff est la plateforme de gestion centralisée dédiée aux équipes pédagogiques (formateurs) et aux administrateurs généraux d'Evolve Academy. L'application fournit les interfaces nécessaires pour créer les contenus éducatifs, modérer le catalogue, animer les formations, encadrer les étudiants et piloter la santé financière de l'école.

Périmètre et Acteurs Cibles

Rôle Missions Principales Droits & Accès Système
Formateur
teacher		 Gestion des cours, ajout de leçons et fichiers, création et correction de devoirs, suivi de la progression des inscrits, réponse aux questions des apprenants. Accès restreint à ses propres cours créés, aux soumissions d'étudiants rattachées et à ses conversations directes.
Administrateur
admin		 Modération et validation des cours (mise en ligne), gestion des utilisateurs (rôles, invitations), grand livre financier, suivi des indicateurs clés et de la trésorerie. Accès étendu via Edge Functions sécurisées avec contournement contrôlé du RLS pour les analyses globales.
Étudiant
student		 Apprentissage via le portail étudiant web (Evolve School). Refusé sur Evolve Staff : rejet immédiat à la connexion après validation du rôle.

2. Architecture Globale du Système

L'architecture repose sur une séparation claire entre un client riche multiplateforme (Flutter) et un Backend-as-a-Service hautement sécurisé (Supabase PostgreSQL).

Règles de Cloisonnement et d'Intégrité

  • Clé Publique Uniquement : Le code client Flutter n'initialise que la clé anonyme publique Supabase (publishableKey). La clé service_role est rigoureusement proscrite de l'application cliente.
  • Chiffrement en Transit : Toutes les communications utilisent TLS 1.3 (HTTPS) et WebSockets sécurisés (WSS) pour le temps réel.
  • Traitement des Données Sensibles : Les transactions financières et modifications de droits sont déléguées à la base PostgreSQL ou aux Edge Functions pour empêcher tout contournement côté client.

6. Sécurité, Rôles et RLS (Row-Level Security)

Prévention de l'Élévation de Privilège

Une faille classique des architectures BaaS consiste à laisser un utilisateur authentifié modifier son propre champ role dans sa table de profil via l'API client. Sur Evolve Academy, ce vecteur est totalement verrouillé :

-- Trigger de protection exécuté avant insertion ou mise à jour
CREATE OR REPLACE FUNCTION public.guard_profile_role_assignments()
RETURNS trigger LANGUAGE plpgsql AS $$
BEGIN
  IF auth.role() = 'authenticated' THEN
    IF TG_OP = 'INSERT' AND NEW.role IS DISTINCT FROM 'student' THEN
      RAISE EXCEPTION 'New accounts cannot assign their own privileged role'
        USING ERRCODE = '42501';
    END IF;

    IF TG_OP = 'UPDATE' AND NEW.role IS DISTINCT FROM OLD.role THEN
      RAISE EXCEPTION 'Profile roles can only be changed by an administrator'
        USING ERRCODE = '42501';
    END IF;
  END IF;
  RETURN NEW;
END;
$$;

Fonction Sécurisée de Changement de Rôle

Toute promotion ou rétrogradation passe obligatoirement par la procédure stockée public.admin_update_profile_role qui impose 3 règles de sécurité majeures :

  1. Authentification Admin Requise : L'appelant doit posséder le rôle admin actif.
  2. Protection Anti-Suicide : Un administrateur ne peut pas rétrograder son propre compte, garantissant qu'il ne se retire pas accidentellement ses droits.
  3. Garantie du Dernier Administrateur : Un verrou de table SHARE ROW EXCLUSIVE empêche toute condition de concurrence qui aboutirait à un système avec 0 administrateur.

7. Supabase Edge Functions (Deno / TypeScript)

Les Edge Functions fournissent une couche d'abstraction et d'orchestration pour les opérations nécessitant des droits d'administration étendus sans exposer la base brute au client.

Fonction Rôle & Traitement Sécurisation
admin-dashboard Agrège en une seule requête les compteurs d'utilisateurs (7 derniers jours, étudiants, formateurs, admins), les statuts de cours et les paiements en attente. Vérifie le token JWT et le rôle admin avant de calculer les totaux.
admin-analytics Génère les tendances chronologiques mensuelles des inscriptions, de la rétention et de la ventilation des revenus. Filtrage strict des entrées et isolation des métriques sensibles.
admin-users Retourne la liste paginée des comptes enregistrés avec recherche plein texte sur nom et e-mail. Empêche la fuite de données personnelles vers des comptes non autorisés.
invite-admin Déclenche l'envoi d'un e-mail d'invitation sécurisé via le système d'authentification Supabase. Restreint aux administrateurs actifs ; configure le rôle cible dès validation de l'invitation.
admin-financials Enregistre et consolide les écritures comptables du grand livre (dépenses et remboursements). Vérifie l'existence et la validité de l'inscription remboursée.

8. Messagerie Temps Réel Étudiant-Formateur

La messagerie permet un encadrement pédagogique direct. Les messages sont échangés via les tables conversations et direct_messages avec synchronisation instantanée bidirectionnelle.

9. Module Financier et Reporting Comptable

Le module de trésorerie (revenue_screen.dart) est réservé aux administrateurs pour le suivi rigoureux des recettes générées via la passerelle de paiement Chargily Pay.

Règles de Réconciliation et Traçabilité

  • Devise Unifiée : Tous les montants sont libellés en Dinar Algérien (DZD) et manipulés sous forme d'entiers ou unités mineures pour éliminer les erreurs d'arrondi à virgule flottante.
  • Isolement des Anciens Paiements : Tout paiement historique dépourvu de montant enregistré ou horodaté avant la mise en place des webhooks n'est pas interpolé à partir du prix catalogue actuel du cours. Ces écritures sont isolées avec la mention "paiements historiques sans montant".
  • Saisie des Écritures Manuelles : Les administrateurs peuvent renseigner les charges opérationnelles (serveurs, publicité) et les remboursements étudiants. Le grand livre calcule ainsi le mouvement net exact.

Déploiement Flutter Web sur Vercel

Le fichier vercel.json pilote le build via scripts/build.sh en téléchargeant le SDK Flutter 3.35.7 dans l'environnement conteneurisé. Les en-têtes HTTP désactivent la mise en cache sur index.html, version.json et flutter_service_worker.js pour éviter que les utilisateurs ne conservent une version obsolète de l'application.

12. Maintenance, Dépannage et Exploitation

Problème Rencontré Cause Racine Probable Résolution Recommandée
Accès refusé au login : "You are not authorized" Le profil utilisateur possède le rôle student ou la colonne role est nulle. Un administrateur doit changer le rôle vers teacher ou admin dans Supabase.
Liste d'utilisateurs ou finances bloquée en chargement L'Edge Function correspondante n'est pas déployée ou le jeton JWT a expiré. Consulter les journaux de logs dans le dashboard Supabase et redéployer la fonction.
L'export CSV ne se déclenche pas sous navigateur Politique stricte du navigateur bloquant les téléchargements automatiques. Autoriser les pop-ups et téléchargements pour l'URL de l'application staff.
Nouveau cours bloqué en statut brouillon Un formateur ne peut pas s'auto-valider. Un administrateur doit approuver et publier le cours depuis la section modération.
Règle de sécurité impérative : Ne jamais intégrer de clé service_role ou de secret d'API Chargily dans les variables d'environnement de l'application Flutter. Toutes les opérations privilégiées doivent continuer à transiter par les Edge Functions ou les fonctions PostgreSQL avec SECURITY DEFINER.
